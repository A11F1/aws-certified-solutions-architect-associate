## 🎯 About this Repository

This repository combines open-source material with a focus on real architectural reasoning: trade-offs, use cases, exam pitfalls, low-cost curated labs, and practical questions in the style of the SAA-C03 exam.

This material was structured for an intermediate-level student who already uses AWS day to day and already knows cloud fundamentals. The focus is not blind memorization: the goal is to develop the reasoning expected of a solutions architect, understanding the trade-offs between resilience, performance, security, and cost.

The repository was designed to work well on GitHub. Each module contains theory, exam-style questions, flashcards, a cheatsheet, architectural scenarios, labs, and a curated list of official links. The order of the modules follows the most heavily tested topics on the exam and a progression of complexity that makes sense for a 9-week review.


## 🖥️ Interactive Portal

In addition to GitHub Pages, the repository includes a single-file study portal (`aws-saa-portal.html`) that can be opened directly in the browser — no installation, no build.

**What it does:**

- Lists the 31 modules in a sidebar, with search and an "All / Pending / Completed" filter.
- Loads the content of each module directly from this repository (via GitHub raw) and renders it as formatted markdown.
- Tracks progress module by module — the checkmark and the progress bar are saved in the browser (`localStorage`), with no login or backend required.
- Shows progress by exam domain (resilience, performance, security, cost).
- Each module has a shortcut to open the corresponding `README.md`/`lab.md` directly on GitHub. 

**How to use:** download `aws-saa-portal.html` and open it locally, or host it as a static page (GitHub Pages itself works).

## 🚀 How to Use This Repository

1. Start with module 01 to align expectations, weights, and strategy.
2. Study modules 02 through 25 in order and use the lab modules to consolidate the critical topics.
3. At the end of each module, solve the questions before opening the answer key.
4. Use flashcards for spaced-repetition review and the cheatsheet for quick pre-exam review.
5. Run the labs in us-east-1 whenever possible to stay consistent with the material.
6. Finish your preparation with case studies, end-to-end labs, practice exams, the error notebook, and review by domain.

1. Read the module README to understand the context, services, and exam signals.
2. Review the cheatsheet before solving questions.
3. Solve the questions without opening the answer block.

- Compare S3, EBS, EFS, FSx, and storage classes.
- Practice VPC, endpoints, NAT Gateway, security groups, NACLs, and routing.
- Redo wrong questions before starting new practice exams.

## ⚠️ Common exam pitfalls

| Frequent confusion | When to use each option | Typical exam trap |
|---|---|---|
| SNS vs SQS | SNS for pub/sub fanout; SQS for a decoupled queue with asynchronous processing and consumption control. | Confusing broadcast to multiple consumers with a point-to-point queue. |
| SQS Standard vs FIFO | Standard for high throughput and tolerance for duplicates/eventual ordering; FIFO for strict ordering and deduplication. | Choosing FIFO unnecessarily and losing scale, or choosing Standard when ordering is mandatory. |
| RDS Multi-AZ vs Read Replicas | Multi-AZ for high availability and failover; Read Replicas to scale reads and reporting. | Assuming Multi-AZ improves reads or that a replica replaces synchronous HA. |
| NAT Gateway vs VPC Endpoint | NAT Gateway for general private outbound access to the internet; VPC Endpoint for private access to AWS services without the internet. | Using NAT for S3/DynamoDB and paying more, even though an endpoint is available. |
| ALB vs NLB vs CLB | ALB for HTTP/HTTPS layer 7; NLB for TCP/UDP/TLS layer 4 and low latency; CLB for legacy. | Ignoring the protocol requirement and sticky/session routing. |
| S3 Standard vs IA vs One Zone-IA vs Glacier | Standard for frequent access; IA for infrequent access; One Zone-IA for reproducible data; Glacier for archiving. | Choosing a cheap class without considering retrieval latency and minimum retention. |
| EBS vs EFS vs FSx | EBS for block storage on EC2; EFS for multi-AZ Linux NFS sharing; FSx for specialized file systems (Windows, Lustre, ONTAP, OpenZFS). | Treating EBS as shared across multiple instances without a specific architecture. |
| ASG vs scheduled scaling vs predictive scaling | ASG for automatic elasticity based on metrics; scheduled for predictable events; predictive for historical patterns. | Using only scheduled scaling on unpredictable load and losing resilience at peaks. |
| API Gateway vs ALB for Lambda | API Gateway for managed APIs with auth, throttling, and versioning; ALB for simple HTTP routing with Lambda integration. | Choosing ALB when the question asks for advanced API management features. |
| KMS CMK vs Secrets Manager vs SSM Parameter Store | KMS for encryption/keys; Secrets Manager for rotation and sensitive secrets; Parameter Store for parameters and simple secrets. | Thinking KMS alone solves the secrets lifecycle. |
